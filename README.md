# POCUS MOSCOW Block Planner

Интерактивный образовательный навигатор выбора стратегии регионарной
анестезии по типу операции.

Первая демонстрационная операция — тотальное эндопротезирование коленного
сустава (TKA / ТЭКС). Версия 0.6 открывается интерактивным Digital Human Atlas:
согласованный набор Higgsfield-сцен и управляемый камерой переход к пяти
клиническим направлениям. Для паравертебральной и нейроаксиальной навигации
используется задняя проекция модели; верхняя конечность показывает перелом
хирургической шейки плеча, нижняя — эндопротез тазобедренного сустава.

Раздел грудной и брюшной стенки содержит 12 интерактивных сценариев — от
торакотомии и VATS до лапаротомии, кесарева сечения и паховой герниопластики.
Для каждого сценария соматическое покрытие стенки отделено от висцерального
компонента, показаны обязательные зоны проверки и кандидатные стратегии.

Интерактивная карта фасциальных плоскостей содержит переднюю, боковую и заднюю
проекции для PEC I–II, deep serratus, SPIP, DPIP, classic/subcostal TAP,
rectus sheath и lateral/posterior/anterior QL blocks (QLB 1–3).

Версия также содержит интерактивный модуль верхней конечности для взрослых 18+:

- 9 типовых операций от ключицы до пальцев;
- сравнение кандидатных стратегий и риска диафрагмальной дисфункции;
- расчёт экскурсии диафрагмы и thickening fraction;
- арифметический калькулятор массы местного анестетика и мг/кг;
- контрольные блоки LAST и антитромботической терапии (ASRA 2025).

Сценарий показывает переход:

`операция → хирургическая зона → иннервация → покрытие → слепая зона → стратегия`

> Проект не является клинической рекомендацией. Клинические формулировки и
> визуальная карта требуют экспертной валидации перед практическим применением.
> Дозовые пределы и числовые интервалы антитромботической терапии намеренно
> заблокированы до утверждения локального протокола.

## Локальный запуск

```bash
npm ci
npm run dev
```

## Проверка

```bash
npm run build
npm run lint
```

## Структура

- `app/` — интерфейс и scroll-механика;
- `public/media/` — оптимизированные визуальные материалы;
- `docs/` — Style Bible, промпты и роли LLM;
- `.github/workflows/` — автоматическая проверка сборки.

## Работа с клиническим контентом

Каждое утверждение должно иметь один из статусов:

- `VERIFIED` — проверено экспертом;
- `NEEDS REVIEW` — требует клинической проверки;
- `PROTOTYPE LOGIC` — используется только для демонстрации интерфейса.

Проект не хранит данные пациентов.
